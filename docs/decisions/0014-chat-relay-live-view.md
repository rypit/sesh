# 0014. The gateway in the chat path, for a live browser view inside Open WebUI

- Status: accepted
- Date: 2026-11-28
- Feature: specs/010-browser

## Context

The household wants to see the agent's browser in the chat itself: a
small live window in the message, a larger window to take over, and
control handed back when it's closed. Not a one-time link. Open WebUI
v0.13.5 can show such a window: an SSE chunk carrying
`{"event": {"type": "embeds", ...}}` on an OpenAI-compatible stream
adds an iframe embed to the message (specs/010 research.md R1). The
model never sees embeds. But someone has to add that chunk, and know
which person is chatting.

## Decision

1. **Open WebUI talks to each agent runtime through the gateway.**
   - Open WebUI connects to the gateway's chat listener (`:7003`, on a
     new `chat` pair network), with the agent's API key.
   - The gateway forwards requests to `hermes-<agent>:8642` unchanged
     and streams the reply back.
   - Open WebUI no longer reaches any runtime directly (the
     `agent-<agent>-chat` network is removed).
2. **The person is identified by Open WebUI's signed user header**
   (`X-OpenWebUI-User-Jwt`, HS256, with a secret shared with the gateway
   and generated by `sesh init`).
3. **When the agent's browser is in use during a request, the gateway
   adds one embed chunk** pointing at a live view page on the approvals
   listener. The page's grant is bound to that Open WebUI user, the agent
   and the session, with its secret in the URL fragment, stored hashed,
   and expiring 30 minutes after last use.
4. **View and input pass through the gateway.**
   - Frames come from CDP screencast.
   - Input is accepted only from the larger window, and only while the
     person has taken over.
   - While the person is in control, the agent's browser calls wait and
     then fail.
   - Closing the window hands control back.
   - Everything is audited, without typed text.

## Alternatives

- **An Open WebUI function that injects the embed**: code in Open
  WebUI's database. Rejected (constitution VI).
- **A one-time link via ntfy**: the household rejected it.
- **A separate relay service**: another trusted component, which would
  need the same knowledge as the gateway. Rejected.
- **MCP Apps in Open WebUI**: Open WebUI would have to run the agent's
  tools itself. Rejected.

## Consequences

- **The gateway carries chat traffic.** A gateway restart interrupts
  chats in flight, as a runtime restart does today.
- **What talks to what changes:** Open WebUI talks to the gateway (new),
  and no longer to runtimes. Diagram and layout updated.
- **Leaked links:** a live view link copied out of a chat expires
  quickly and needs its fragment secret. It grants view and takeover of
  one agent's browser, never credentials.
